# Immersio — Backend

Immersio is a Japanese-language **immersion learning** platform. Learners browse a
**curated catalog** of Japanese videos and can also **submit their own** favourite
YouTube videos to learn from. For every video, the backend ingests the Japanese
captions, analyses the language, turns it into study material (pronunciation
"shadowing" practice, in-context word explanations, difficulty profiles), and tracks
each learner's progress to personalize what they study next.

This repository is the **FastAPI backend** only — the API, business logic, data
models, and integrations with the external services that power ingestion and AI
features. The web frontend lives in a **separate repository** and consumes this API.

---

## Core Features

### 1. Video ingestion & language processing
- Two content paths through the same pipeline: admins add **curated** videos, and
  learners **submit** their own YouTube videos by URL. Either way the system
  validates the video and pulls its metadata and Japanese caption track.
- Captions are tokenized with Japanese morphological NLP (**fugashi + unidic**) and
  looked up against **JMdict** for meanings and JLPT difficulty tiers.
- Each video gets a **vocabulary profile** (which words appear, how often) and a
  per-video difficulty picture.
- Videos without human captions are transcribed asynchronously with **Whisper**;
  long-running work runs in the background so the API responds immediately.

### 2. Shadowing (pronunciation practice)
- Captions are reconstructed into clean, sentence-level units for the learner to
  listen to and repeat ("shadow").
- Human-captioned videos are processed synchronously; auto-captioned videos build
  their shadowing sentences in the background, with a readiness flag the client can
  poll.

### 3. AI-generated explanations
- On demand, learners get **word-in-context** and **pronunciation-feedback**
  explanations generated by **Google Gemini** with structured (schema-bound) output.
- Explanations are cached so repeated lookups are fast and cheap.
- English meanings are supported via **Google Cloud Translate**.

### 4. Learning analytics & spaced repetition
- **Learning sessions** record what a learner watched and for how long.
- **Daily progress** rolls up study time, videos watched, new/known vocabulary, and
  streaks.
- **Vocabulary exposure** tracks how often a learner has met each word, building a
  per-user knowledge profile.
- A **spaced-repetition** system (SM-2: ease factor, intervals, lapses) schedules
  vocabulary reviews and logs every graded review.

### 5. Personalized recommendations
- A per-user video feed built on **comprehensible-input** theory (Krashen's *i+1*):
  it favours videos the learner can mostly understand while still meeting some new,
  level-appropriate words.
- Each candidate video is scored on four signals — **comprehension fit**,
  **learning value**, **spaced-repetition review value**, and a **recency penalty** —
  then ranked and grouped into difficulty sections ("Top picks", "Just Right",
  "Challenge", "Easy For You").
- New learners get a level-based cold-start feed; every scoring constant is
  centralized in one config for easy calibration.
- See [docs/recommendation_technical_report.md](docs/recommendation_technical_report.md)
  for the full design, math, and references.

### 6. Accounts, roles & admin
- **JWT authentication** (access + refresh tokens), bcrypt-hashed passwords, and a
  self-service profile (including the learner's proficiency level).
- **Role-based access** (`ADMIN` / `LEARNER`); admins manage the video catalog and
  users through a separate router surface.
- **Soft-delete** everywhere — deactivated users and videos are hidden from the
  public feed but retained for admins; no hard deletes.

## Getting Started

### Prerequisites
- Python 3.12
- Docker (for PostgreSQL), or a local Postgres instance
- API credentials in a `.env` file (see below)

### Install
```bash
pip install -r requirements.txt
python -m unidic download        # one-time: dictionary for fugashi tokenization
```

### Configure
Create a `.env` with at least:
```
DATABASE_URL=postgresql+psycopg://postgres:postgres@localhost:5432/immersio
YOUTUBE_API_KEY=...
GEMINI_API_KEY=...
SECURITY_KEY=...
ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=...
REFRESH_TOKEN_EXPIRE_DAYS=...
```
Google Cloud Translate credentials are read from `gct_key.json`.

### Run
```bash
docker compose up -d             # start PostgreSQL (port 5432)
uvicorn main:app --reload        # API at http://localhost:8000, docs at /docs
```
Database tables are created automatically at startup.

## Testing

```bash
pytest                     # everything
pytest -m unit             # fast, no I/O
pytest -m integration      # needs a Postgres test database
pytest -k "keyword"        # by name substring
```

- **Unit vs integration** is expressed with **pytest markers**, not folders.
- Integration tests need a real Postgres test DB (several models use JSONB, which
  SQLite cannot create). Set `TEST_DATABASE_URL`
  (default `postgresql+psycopg://postgres:postgres@localhost:5432/immersio_test`).
  If the DB is unreachable, those tests **skip** rather than fail.

```bash
ruff check .
ruff format .
```

## Architecture

A strict **layered architecture**; data flows one direction and layers mirror each
other by domain name:

```
api/v1/endpoints/  ─ thin FastAPI routers: parse request, check auth, call a service
services/          ─ all business logic, orchestration, and DB access (grouped by domain)
utils/             ─ pure helpers: NLP, caption parsing, dictionary lookup, scoring math
models/            ─ SQLAlchemy ORM (one file per table)
schemas/           ─ Pydantic request/response models
core/              ─ cross-cutting configuration (e.g. recommendation tuning)
db/base.py         ─ engine, session, Base, and the get_db() dependency
```

- **Endpoints never touch the DB directly** — they inject a session and the current
  user, then delegate to a service.
- **Services own transactions** and coordinate other services and utilities.
- **Long-running work** (Whisper transcription, video vocabulary profiling) is
  deferred to background tasks; endpoints return immediately.
